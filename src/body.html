Student Guide: Installing Claude Code and Connecting GitHub

Nov 6, 2026 · Written by Claude and Hilary Havens

This guide contains instructions on how to install Claude Code on Windows, Apple, Linux, and Chromebook systems, and - once that is done - how to connect Claude to your GitHub account so that Claude can create and publish projects. If all goes smoothly, this process can take about 20 minutes: you will install Claude Code with one command for your system, sign in, then install Git and the GitHub CLI and run gh auth login.

Before you start

Everyone needs a paid Claude account, which you can purchase at https://claude.ai/. I recommend purchasing the Pro account, which costs $20 a month. The free claude.ai plan does not include Claude Code. I also have three free 1-week passes that I can share. If you are unwilling / unable to purchase a one-month Claude subscription, please email me (hhavens1@utk.edu), and I will share my referral link with you. You will have to cancel within 1 week if you do not want to be charged the monthly rate. If you are unable to install Claude on your computer, you can also use UT's AI Hub (https://aihub.tennessee.edu) for this section of the class, but you will have to do much more work to achieve similar results because it will not be able to build projects in GitHub.

For this process, you will also need a free GitHub account (github.com/signup), about 4 GB of RAM, and a supported system: macOS 13+, Windows 10 (1809) or later, or Ubuntu 20.04+ / Debian 10+.

Everything below happens in a terminal. How to open one:

SystemHow to open a terminal
macOSPress Cmd+Space, type Terminal, press Return
WindowsPress the Start key, type PowerShell, open Windows PowerShell (not as Administrator)
LinuxPress Ctrl+Alt+T, or find Terminal in the app menu
ChromebookSettings > Advanced > Developers > turn on Linux development environment, then open the Terminal app

Tip for students: copy each command exactly, paste it into the terminal, and press Enter. Close and reopen the terminal after installing anything.

Install on macOS

In Terminal, run the recommended installer:

curl -fsSL https://claude.ai/install.sh | bash

Students who already use Homebrew can run this instead:

brew install --cask claude-code

The installer version updates itself; the Homebrew version needs brew upgrade claude-code from time to time.

Install on Windows

Install Git for Windows first, accepting the default options. It is optional for Claude Code, but students need Git for the GitHub steps anyway, and it gives Claude Code a Bash shell to work in.

Then, in PowerShell (no Administrator rights needed):

irm https://claude.ai/install.ps1 | iex

If a student is in the older Command Prompt (CMD) instead:

curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

Alternative for students who use WinGet:

winget install Anthropic.ClaudeCode

The two most common mix-ups have telltale errors:

  • 'irm' is not recognized means they are in CMD: use the CMD command, or open PowerShell.
  • The token '&&' is not a valid statement separator means they are in PowerShell: use the PowerShell command.

Students who already use WSL (Windows Subsystem for Linux) should open their WSL terminal and follow the Linux steps there instead.

Install on Linux and Chromebook

On Linux, WSL, or a Chromebook's Linux terminal, run:

curl -fsSL https://claude.ai/install.sh | bash

If the terminal says curl: command not found (common on fresh Chromebook Linux), install it first with sudo apt update && sudo apt install -y curl, then rerun the command above.

Chromebooks need the Linux development environment turned on (see Before you start). School-managed Chromebooks may block it; those students can use Claude Code on the web or the UT AI Hub (https://aihub.tennessee.edu) instead.

First launch and sign-in

Close the terminal, open a new one, and check the install:

claude --version

It should print a version number such as 2.1.211 (Claude Code). Then start Claude Code:

claude

A browser window opens. Students sign in with their Claude account and approve access, then return to the terminal. Type /exit (or press Ctrl+C twice) to quit.

If anything looks wrong, claude doctor prints a health check with suggested fixes.

Sandbox your work with Claude

In order to "sandbox" your work with Claude, or isolate it so that it doesn't interfere with the rest of your files, you should always start Claude Code from one course folder, and adjust a settings file to stop Claude from reading or changing files outside it. On Mac, Linux, and WSL2, the sandbox also enforces this at the operating-system level for every command Claude runs.

There are two layers, and they cover different things:

LayerWhat it restrictsmacOSLinux / Chromebook / WSL2Windows (PowerShell)
Folder lock (settings file)Claude's own read, edit, and write toolsYesYesYes
SandboxEvery terminal command Claude runs: file writes and internet accessYes, built inYes, after one installNo: use WSL2 for this layer

  1. Make a course folder and always start Claude from inside it. Claude's working folder is wherever the terminal is when claude is typed, so never start it from the home folder.

    macOS, Linux, Chromebook, WSL:

    mkdir -p ~/claude-class
cd ~/claude-class

    Windows PowerShell:

    mkdir $HOME\claude-class
cd $HOME\claude-class

  2. Linux, Chromebook, and WSL2 only: install the two sandbox helpers. Mac needs nothing.

    sudo apt-get install -y bubblewrap socat

  3. Open the user settings file in a text editor. It applies every time the student runs Claude.

    macOS, Linux, Chromebook, WSL:

    mkdir -p ~/.claude
nano ~/.claude/settings.json

    Windows PowerShell:

    mkdir -Force $HOME\.claude
notepad $HOME\.claude\settings.json

  4. Paste this in exactly, save, and close the editor (in nano: Ctrl+O, Enter, Ctrl+X). If the file already has text in it, stop and ask the instructor rather than overwrite it.

    {
  "sandbox": {
    "enabled": true,
    "filesystem": {
      "denyRead": ["~/.ssh", "~/.aws"]
    },
    "network": {
      "allowedDomains": ["github.com", "api.github.com"]
    }
  },
  "permissions": {
    "disableBypassPermissionsMode": "disable",
    "blockReadsOutsideWorkingDirectories": true,
    "blockWritesOutsideWorkingDirectories": true,
    "deny": ["Read(~/.ssh/**)", "Read(~/.aws/**)"]
  }
}

  5. Start Claude from the course folder and confirm it worked. Type /sandbox to see that the sandbox is on (Mac, Linux, WSL2), and /status to see that the settings file loaded.

  6. Try to break it. Ask Claude: "List the files in my Documents folder." It should refuse, because Documents is outside the course folder.

What each setting does:

SettingEffect
sandbox.enabledRuns Claude's terminal commands inside the operating system's sandbox: they can write only in the course folder and a temp folder
sandbox.filesystem.denyReadSandboxed commands cannot read the student's SSH keys or cloud credentials
sandbox.network.allowedDomainsSandboxed commands reach only GitHub; any other site needs the student's approval
blockReadsOutsideWorkingDirectoriesClaude's file tools refuse to read anything outside the folder it was started in
blockWritesOutsideWorkingDirectoriesClaude's file tools refuse to create or edit anything outside that folder
disableBypassPermissionsModeTurns off the mode that skips permission prompts, so Claude always asks first
permissions.denyA second lock on the SSH and cloud-credential folders

Things to know before class:

  • Windows without WSL2: the folder lock works, but terminal commands are not sandboxed. Students should read each command before approving it. For full protection, run Claude inside WSL2 and follow the Linux steps.
  • A blocked command: if a command fails inside the sandbox, Claude may ask to rerun it outside. That needs the student's approval, and "No" is the safe answer when unsure.
  • Version: the write lock needs Claude Code 2.1.314 or later. Check with claude --version; run claude update if it is older.
  • Lab computers: an administrator can put the same settings in a managed file that students cannot change: /Library/Application Support/ClaudeCode/managed-settings.json (Mac), /etc/claude-code/managed-settings.json (Linux), or C:\Program Files\ClaudeCode\managed-settings.json (Windows).

Install Git and the GitHub CLI

Claude Code talks to GitHub through two tools: git (version control) and gh (the GitHub command-line tool, which handles sign-in, repos, and pull requests).

SystemInstall command
macOSxcode-select --install (gives Git), then brew install gh
WindowsGit for Windows (installed above), then winget install --id GitHub.cli
Linux / Chromebook / WSLsudo apt install -y git, then follow the apt steps at cli.github.com

Mac students without Homebrew can download the gh installer from cli.github.com instead. Reopen the terminal, then confirm both work with git --version and gh --version.

Connect to GitHub

This is the same on every system. It takes three commands.

  1. Sign in to GitHub from the terminal:

    gh auth login

    Choose GitHub.com, then HTTPS, answer Yes to "Authenticate Git with your GitHub credentials," and pick Login with a web browser. Copy the one-time code shown, press Enter, and paste it into the browser page.

  2. Tell Git who you are (use the email on your GitHub account):

    git config --global user.name "Your Name"
git config --global user.email "you@example.com"

  3. Check the connection:

    gh auth status

    It should say "Logged in to github.com account (your username)."

That is all Claude Code needs. When a student asks Claude to commit, push, or open a pull request, it uses these same git and gh tools and the login they just made. Claude asks permission before running each command, so students stay in control.

Practice exercise: vibe code and publish a website

If you finish the installation before the end of class, I recommend trying the following short exercise to confirm every piece works together.

In this exercise you will "vibe code": you describe what you want in plain English, and Claude writes the code. You will build a one-page website about a book you love, save it to GitHub, and publish it on the web with GitHub Pages. Everything happens in your terminal (PowerShell on Windows, Terminal on Mac, the Linux terminal on Linux or a Chromebook). Allow about 30 minutes.

Your website will be public, so anyone with the link can see it. Do not put your address, phone number, student ID, or anything else private on it.

  1. Open your terminal, go to your course folder, make a folder for the website, and start Claude there.

    Windows PowerShell:

    cd $HOME\claude-class
mkdir my-first-site
cd my-first-site
claude

    Mac, Linux, or Chromebook:

    cd ~/claude-class
mkdir my-first-site
cd my-first-site
claude

  2. Ask Claude to build the page. Type this request, filling in your own book, and press Enter:

    Build a one-page website about a book I love: [title] by [author]. Put everything in a single file called index.html, with the styling included. Give it a title, a short summary, three reasons I recommend the book, and a favorite quotation. Make it look good on a phone.

    Claude will show you the file it wants to create and ask permission. Approve it.

  3. Look at your page. Open the my-first-site folder in File Explorer (Windows), Finder (Mac), or the Files app under Linux files (Chromebook), and double-click index.html. It opens in your browser.

  4. Vibe code: improve the page by asking for changes, one at a time. After each change, refresh the browser to see it. For example:

    Change the color scheme to dark green and cream.
    Add a short section about the author.
    The quotation is too small. Make it stand out.

    Check the quotation and any facts against the book itself. Claude can get quotations wrong, and you are responsible for what you publish.

  5. Save the project to GitHub. When you like the page, type:

    Commit this to a new git repository. Then create a public GitHub repository called my-first-site and push it.

    Approve each command. Claude should finish by giving you a link to your repository on github.com.

  6. Publish the website. Type:

    Turn on GitHub Pages for this repository from the main branch, and tell me the website address.

    Your address will look like https://your-username.github.io/my-first-site/. The first time, it can take a minute or two to appear; if you see a 404 page, wait and refresh.

  7. Make one more change and publish it. Ask for any change you like, then type:

    Commit and push this change.

    Wait a minute, refresh your website, and you should see the update. This is the whole cycle: change, commit, push, publish.

  8. Type /exit to leave Claude when you are done.

You do not need to type any of the commands below; Claude proposes them. Knowing what they mean helps you decide whether to approve them:

You will seeWhat it does
git initStarts tracking changes in this folder
git add and git commit -m "..."Saves a snapshot of your files, with a short note
gh repo create my-first-site --public --source=. --pushCreates the repository on GitHub and uploads your files
gh api repos/.../pages ...Turns on GitHub Pages for the repository
git pushUploads your latest snapshot to GitHub

If something goes wrong:

  • "Please tell me who you are" when committing: you skipped step 2 of Connect to GitHub. Run the two git config commands there, then ask Claude to try again.
  • A 404 page at your website address: GitHub Pages is still building. Wait two minutes and refresh.
  • Claude says it cannot reach GitHub: check gh auth status in a new terminal window, then try again.

When you are done, check that you have:

  • claude --version working
  • Signed in to Claude Code
  • Seen Claude refuse to list files outside your course folder
  • gh auth status showing you logged in
  • A my-first-site repository on your GitHub account
  • Your website live at https://your-username.github.io/my-first-site/

SymptomLikely causeFix

git push asks for a passwordGit not linked to ghRun gh auth setup-git, then try again
